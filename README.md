# Maven dependency cache

This `maven-cacher` job periodically generates and distributes a pre-populated Maven local repository archive. The archive is intended to accelerate Maven builds running on ephemeral Jenkins agents by avoiding the need to download commonly used dependencies on every build.

## Archive content

The cache is populated using the following sources:

- **Jenkins BOM**: dependencies required by the `sample-plugin` project, including runtime, compile and test dependencies.
- **Jenkins Core**: dependencies required by the Jenkins Core release branches corresponding to the release lines supported by the BOM.
- **Additional dependencies**: artifacts listed in [`missing-deps.txt`](./missing-deps.txt), covering dependencies not retrieved by the previous steps.

The BOM's `sample-plugin/pom.xml` is used as the source of truth for supported release lines.

Before archiving, the following files are removed from the local repository:

- `_remote.repositories`: Maven repository-specific resolution metadata.
- `*.lastUpdated`: cached resolution failures that could otherwise prevent subsequent dependency resolution.

The default `archiveName` on top of the pipeline can be changed in a replay to generate and upload archives with other names and/or compression format.

The compression format is determined from the archive filename extension. Supported formats:
- `.tar`: no compression
- `.tar.gz`: GZIP (medium compression)
- `.tar.zst`: Zstandard (best compression)

## Jenkins pipeline

The pipeline is defined in [`Jenkinsfile`](./Jenkinsfile) and runs weekly (Sunday at 00:00 UTC).

It executes the following stages:

1. **Checkout and checks**: checks out this repository and verifies the availability of the required command-line tools.
2. **Retrieve existing cache**: downloads the previously published archive from the source Azure Files share and extracts it into the agent's Maven local repository. This allows the cache to be incrementally reused rather than generated from scratch.
3. **Populate cache**: runs ./populate-cache.sh to resolve dependencies.
4. **Create archive**: runs ./create-archive.sh to generate a new archive.
5. **Check archive**: runs ./check-archive.sh to verify that the generated archive is not empty and records its size, number of files and number of directories in the build description.
6. **Upload archive**: publishes the archive to all configured storage backends in parallel.

### Storage backends

The pipeline supports Azure Files shares and AWS S3 buckets.

The configured destinations are:

- `cache-east-us-2` Azure fileshare in `cacheeastus2` storage account
- `cache-sweden-central` Azure fileshare in `cacheswedencentral` storage account
- `ci-jenkins-io-maven-cache` AWS S3 bucket

`cache-east-us-2` is used as the source for retrieving the existing archive, reflecting the region of `infra.ci.jenkins.io` agents.

Both Azure Files and S3 upload scripts preserve the previous archive before publishing a replacement by making a remote copy of the existing remote archive (if it exists) with `.backup` as suffix, accompagned by a `.backup_datetime` marker containing current datetime.

Azure Files access is performed using short-lived, read/write SAS URLs generated by `get-fileshare-signed-url.sh`. AWS S3 access uses Jenkins-managed AWS credentials.

### Local execution

The Maven cache can also be generated locally by running:

```bash
ARCHIVE_NAME=maven-cache.tar.zst ./populate-cache.sh && ./create-archive.sh
```

By default, the script uses the current working directory for source checkouts and archive generation and `~/.m2/repository` as the Maven local repository.

These locations can be overridden using `ARCHIVE_FOLDER` and `MVN_LOCAL_REPO`, respectively.

The `missing-deps.txt` file can be updated to include additional Maven artifacts. Each non-comment entry must follow this format:

```text
groupId:artifactId:packaging:version
```
